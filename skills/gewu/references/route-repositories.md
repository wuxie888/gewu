# 仓库与源码路线

适用于 GitHub、GitLab、源码包和其他代码项目。

## 只读检查

- 确认仓库归属、默认分支、可见性、当前提交与更新时间
- 阅读 README、LICENSE、NOTICE、贡献与安全说明
- 检查文件树、入口、依赖清单、构建脚本、测试、CI 和 Release
- 阅读核心实现文件和真实数据流，不以目录名或 README 代替源码证据
- 检查 Issues/PR 中的阻塞、维护节奏、兼容性和已知风险
- 查明模型、数据、素材、商标、第三方服务和密钥要求
- 比对官网、演示、文档与当前源码版本

## 证据边界

至少区分：

- 作者或 README 声称
- 源码与仓库元数据直接支持的能力
- 尚未验证的安装、运行和生产条件
- 历史运行记录与本次实际验证

默认不克隆、不安装、不构建、不执行第三方代码。只有用户明确要求“测试、构建、运行、跑一下、来试试”或同义动作时，才在隔离目录中先检查命令、副作用和依赖，再进行低风险验证。“完整看、深查、值不值得用或二开”本身不构成运行授权。

## 视觉补充

若结论依赖 Demo、产品界面、截图、动效或视频，组合网站或媒体路线。源码阅读不能证明托管演示当前可用，浏览 Demo 也不能证明公开仓库包含相同实现。
