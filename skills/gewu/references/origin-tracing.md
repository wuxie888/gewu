# 来源反查

原文不提供产品名、网站或仓库，不是调查终点，而是来源反查的起点。

## 1. 建立线索表

从原页面、图片、视频和上下文提取：

- 产品名、项目名、团队名、作者名和账号
- Logo、图标、品牌色和界面布局
- 标题、按钮、菜单、占位符、报错和独特句子
- 域名片段、浏览器地址栏、二维码和水印
- 命令、包名、API、模型名、配置字段和文件名
- 版本号、Star 数、发布日期、榜单名次和时间描述
- 定价、功能组合、案例名称和输出格式

截图中的文字先转成准确可搜索短语。不要因为图片被裁切就忽略边缘、地址栏或状态栏信息。

## 2. 分层搜索

优先使用最具辨识度的组合：

1. 精确搜索独特英文句子、按钮文案、报错或命令
2. 组合功能名、模型名、时间、作者或发布平台
3. 搜索图片、Logo 或视觉相似页面；工具支持时使用反向图片搜索
4. 在 GitHub 搜索包名、命令、配置字段或独特代码片段
5. 查作者主页、官网、Product Hunt、发布帖、文档和最早提交

普通功能词噪声很大。优先搜索不容易被另一个产品同时拥有的字符串与组合。

## 3. 建立候选而非立即认定

对每个候选比对：

- 名称和作者
- 截图布局、文案与功能
- 发布时间和版本
- 官网、仓库、文档与演示之间的互链
- 原文章描述的限制、价格和输出
- 是否可能是 Fork、套壳、镜像、旧名或二次转载

置信度参考：

- **高**：至少两个独立强线索一致，且官方入口互相印证
- **中**：功能和视觉高度一致，但作者、时间或官方链接仍缺一环
- **低**：只有泛化功能相似，存在多个同类候选

## 4. 找到原始来源

尽量回到：

- 官方网站和官方文档
- 原始 GitHub 仓库而非镜像或聚合页
- 原作者账号和最早发布帖
- 原始论文、演示、视频或产品发布记录

“最早搜到”不等于“最早来源”。根据发布时间、提交历史、互链和作者身份确认。

## 5. 报告证据链

最终说明：

- 锁定的产品/仓库/作者
- 使用了哪些线索
- 候选与原页面的一致点和冲突点
- 是否存在同名、Fork、套壳或旧版本
- 当前置信度与仍缺的证据
- 原始官网、仓库和发布记录链接

无法唯一确认时，不用“就是这个”掩盖不确定性。
