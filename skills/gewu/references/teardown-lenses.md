# 拆解视角

先识别对象，再选择最少但足够的视角。用户点名写作、设计、技术或商业时优先满足，不强制把所有栏目都写一遍。

## 产品与用户价值

- 一句话定位与真实产品形态
- 目标用户、触发场景和替代方案
- 核心任务、主工作流和价值产生位置
- 功能地图、输入、处理、输出和反馈闭环
- 产品当前成熟度：概念、Demo、可用产品或规模化服务
- 差异点是技术、数据、体验、渠道、品牌还是包装
- 使用门槛、付费、账号、地区与集成条件
- 留存、传播和商业模式；没有证据时标为推断

## 技术、源码与运行条件

- 架构、语言、框架、入口、数据流和核心模块
- 模型、API、数据库、第三方服务和部署依赖
- README 声称与实际实现差异
- 测试、CI、Release、Issues 和维护状态
- 性能、成本、隐私、安全与可扩展性
- 哪些能力可复用，哪些必须重写
- 本地验证证据与尚未验证的生产条件

## 网站、设计与交互

- 信息架构、导航和页面层级
- 首屏承诺、视觉焦点和内容节奏
- 关键用户路径、状态、反馈和容错
- 字体、颜色、间距、组件、图像和动效语言
- 演示素材与真实产品界面的边界
- 转化机制、信任信号和阻力
- 可借鉴的设计原则与不能照抄的品牌表达

## 文章、内容与写作风格

- 目标读者、写作目的和核心命题
- 标题、开头钩子、承诺和信息差
- 段落结构、论证顺序、案例和证据
- 语气、人称、句长、节奏、转折与情绪曲线
- 专业信息、故事、观点和营销的比例
- 哪些表达构成作者辨识度
- 可复用的是结构、方法和节奏，不复制受保护原文
- 给出可执行的写作骨架或风格规则，而非只贴形容词

## 商业、传播与增长

- 流量入口、内容包装和传播钩子
- 免费与付费边界、获客和转化路径
- 案例、权威、稀缺性和社交证明
- 是否通过隐藏来源、私信、社群或课程制造信息差
- 真实壁垒与可替代性

## 使用、复刻与二次开发

分别判断，不要混成一个“可行”：

- **使用**：现成产品/项目是否满足用户目的，成本和风险是否可接受
- **复刻外观**：页面与交互能否重做，品牌、素材和版权能否合法替换
- **复刻工作流**：输入、处理和输出链是否能用不同技术实现
- **复刻核心能力**：模型、数据、算法和基础设施是否可得
- **二次开发**：许可证是否允许，代码质量和架构是否值得继承
- **只学方法**：写作、设计、增长或产品结构是否值得吸收

给出保留、替换、重写、不可复制四张清单。若用户明确决定做，再交接到产品化流程。

## 权利与风险

- 代码许可证、NOTICE 与商标
- 文章、图片、视频、数据集、模型权重和用户内容权利
- 隐私、账号、抓取、平台规则和地区限制
- 付费 API、密钥、外部服务锁定和持续成本
- 安全、高风险用途和错误后果

不要把“技术上能做”写成“可以合法、安全、稳定地做”。
