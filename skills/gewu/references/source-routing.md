# 来源路线

按最终内容形态组合使用路线。先完成原页面阅读，再用 API、CLI、搜索、仓库或官方文档核验。

## GitHub 仓库

检查：

- 仓库归属、默认分支、可见性、当前提交与更新时间
- README、LICENSE、NOTICE、贡献与安全说明
- 文件树、入口、依赖清单、构建脚本、测试、CI、Release
- 核心实现文件和真实数据流，不以文件名代替代码阅读
- Issues/PR 中的阻塞、维护节奏、兼容性和已知风险
- 模型、数据、素材、商标、第三方服务和密钥要求
- 官网/演示与当前源码版本是否一致

结论至少区分：仓库真实形态、作者声称、源码证据、本地验证、适用场景、采用风险与是否值得用。

默认不克隆、不安装、不构建、不执行第三方代码。只有用户明确要求测试、构建、运行或“来试试”时，才使用隔离目录并先检查命令与副作用；“值不值得用”不是运行授权。

## 产品网站或在线工具

至少检查：

- 首页定位、目标用户和核心承诺
- 主要导航、功能入口、案例、定价、FAQ 与文档
- 演示、交互、登录前后边界和真实可操作性
- 关键截图、动画和视频是否只是展示素材
- 账号、地区、付费、数据上传与隐私条件
- 官网之外的原仓库、文档、发布记录和团队信息

“整个网站”应界定为会影响产品判断的主要页面，不机械遍历所有法律页、博客归档和无关导航。

## X、社交帖子和连续帖

至少检查：

- 主帖、连续帖、引用帖和作者补充
- 可见回复、作者回复、纠错、反例和社区事实核查
- 每张重要图片、视频、附件和展开内容
- 帖中项目、论文、产品、仓库和演示外链
- 发布日期与项目当前状态的时间差

社交流可能无限。记录已检查回复数量、作者回复数量和停止位置；未遍历无限回复时不要说“所有回复”。

## 微信公众号文章

至少检查：

- 标题、作者、公众号、发布时间和转载来源
- 从开头到文末的正文、分节、重要配图与图中文字
- 嵌入视频、小程序、二维码、原文链接和相关阅读
- 文末声明、广告、版权与来源信息
- 文章隐藏或省略的产品、网站、仓库和原发布
- 文章时间与项目当前状态的差异

验证码、访问频率或环境限制阻塞时，保留原页为未完整项；替代正文或转载只能补充，不能冒充原页面视觉核验。

## 普通文章、博客、新闻和文档

至少检查：

- 标题、作者、日期、正文、脚注、引用、配图和外链
- 事实、观点、案例、推销内容和作者推断的边界
- 一手引用是否支持文章结论
- 文章结构、写作风格和可复用表达方式
- 关键事实是否因时间变化而失效

## PDF、报告和论文

- 确认页数、版本、作者、发布日期和附件关系
- 用户要求完整阅读时逐页检查；无法逐页时明确页码范围
- 图表、注释、附录和方法限制不能只靠正文摘要替代
- 将摘要、作者结论、数据证据与自己的推断分开

## 视频和嵌入媒体

- 检查视频是否为核心证据
- 能完整观看或读取可靠字幕时，记录关键时间点和内容
- 只能看到封面、标题、简介或片段时，明确说明没有完整验证视频
- 不用视频旁边的宣传文案代替视频内容

## 截图、Logo、名称或零散线索

- 先做视觉观察和文字提取，不急于猜产品
- 记录 Logo、界面结构、独特文案、域名片段、版本号、命令和时间线
- 读取 [origin-tracing.md](origin-tracing.md) 建立候选与置信度
- 找到候选后回到对应的产品、仓库、文章或视频路线完成核验
