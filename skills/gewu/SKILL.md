# 格物

格一物，知其然，明其理，辨其值。

把用户给出的目标完整看清，沿关键线索回到一手来源，从适合的维度拆解本质，最后给出有证据的行动判断。不要把正文提取、README 复述或搜索摘要冒充完整研究。

## 不可妥协的规则

1. **先看全，再分析。** 对非 GitHub 页面执行页面级浏览；从顶部看到底部，展开内容并检查重要图片、视频、回复、引用和外链。文本抽取、搜索摘要或单张视口截图只能补充，不能替代页面阅读。
2. **先识别对象，再选择拆解维度。** 区分可运行产品、仓库、技术方案、文章、写作样本、设计案例、商业案例、概念演示和营销素材，不要套用固定报告。
3. **先追一手来源，再相信转述。** 文章未写产品名、网址或仓库时，启动来源反查；从名称、截图、Logo、界面文字、命令、时间线和作者关系寻找官网、原仓库或最早发布记录。
4. **分开事实与判断。** 明确标注直接观察、来源声称、交叉验证、合理推断和未验证内容。
5. **没有覆盖证据，不声称完整。** 最终给出阅读覆盖单；遇到登录、验证码、删除、无限滚动、地区或权限限制时，说明准确边界。
6. **结论必须能指导行动。** 回答是否值得使用、试用、学习、复刻、二开、继续跟踪或停止投入，并说明适用对象、成本、风险和下一步。
7. **调查不自动等于立项。** 默认停在拆解与判断；只有用户明确要求实现、复刻或产品化时，才进入对应开发流程。
8. **保持研究操作安全。** 默认只读。不要擅自克隆、安装、构建、运行第三方代码，也不要登录新账号、付费、上传私有文件、发布内容、修改仓库、部署或触发外部副作用。用户只问“值不值得用”不构成运行授权。

## 工作流

### 1. 接收并界定目标

从链接、仓库、截图、名称、文章或上下文中确定研究对象和用户最关心的判断。只有缺失信息会显著改变研究路线时才问一个简短问题；否则直接开始。

若用户没有指定维度，默认回答：

- 这是什么，当前真实状态如何
- 核心功能、方法或观点是什么
- 最值得借鉴与最值得警惕的部分是什么
- 对用户是否有使用、学习、复刻或二开价值

### 2. 选择来源路线

读取 [source-routing.md](references/source-routing.md)，按最终落地页面而非短链接外观选择路线。一个任务包含多种来源时组合执行。

对需要视觉或交互核验的页面，遵循当前可用的浏览器控制 Skill。用户指定 Chrome 时必须使用 Chrome；未指定时仍把页面级浏览视为任务要求，并让浏览器运行时选择合适页面载体。普通网页读取、API、CLI、连接器和搜索用于补充与交叉验证，不替代视觉阅读。

### 3. 完成页面级阅读

读取 [completeness-checklists.md](references/completeness-checklists.md)。在开始总体判断前确认：

- 已到达有限页面底部，或记录无限内容的实际停止位置
- 已展开所有影响理解的折叠区、标签页和引用内容
- 已逐项检查影响结论的图片、视频、回复和外链
- 已记录数量、范围与访问障碍

“完整”指目标页面和所有影响决策的内容链完整，不要求机械打开隐私政策、无关导航或无限社交流。

### 4. 提取线索并反查来源

当来源明确时，仍确认官网、仓库、作者和版本是否对应；当来源缺失、裁切或故意隐藏时，读取 [origin-tracing.md](references/origin-tracing.md)。

建立候选并逐项比对，不因第一个搜索结果看起来相似就锁定。无法唯一确认时，返回候选、证据、冲突点、置信度与还缺的证据。

### 5. 选择拆解视角

读取 [teardown-lenses.md](references/teardown-lenses.md)，只使用与目标相关的视角：

- 产品与用户价值
- 技术、源码与运行条件
- 网站、设计与交互
- 内容、文章与写作风格
- 商业、传播与增长
- 复刻、采用与二次开发
- 版权、许可证、数据、隐私与平台风险

先说明对象真实形态，再拆功能或风格。没有源码或可运行入口时，不把概念、视频或静态演示描述成成品。

### 6. 独立核验关键说法

读取 [evidence-and-verdict.md](references/evidence-and-verdict.md)。优先核验会改变结论的事项：

- 功能是否真的存在并可访问
- 仓库是否包含实质实现而非 README、Prompt 或壳
- README、官网、截图和代码是否一致
- 许可证、模型、数据、素材和商标边界
- 维护状态、Release、Issues、依赖与当前版本
- 成本、账号、地区、平台政策和安全条件

GitHub 深查默认检查真实文件和官方元数据。只有用户明确说“测试、构建、运行、跑一下、来试试”或同义表达时，才在隔离目录做低风险验证；“完整看、深查、值不值得用”本身不授权克隆、安装或执行。没有运行就不要说“跑通”。

### 7. 形成判断

按用户真实目的给出一项或多项结论：

- **直接使用**：当前可用且条件、风险可接受
- **先做小范围试用**：有价值，但质量、成本或适配仍需实测
- **适合二次开发**：底座可复用，明确列出保留、替换和重写部分
- **适合复刻方法**：学习工作流、交互、写作或产品结构，不照搬品牌与受保护内容
- **只看思路**：有启发，但不宜依赖现成实现
- **继续观察**：方向值得关注，当前尚未成熟或证据不足
- **不值得投入**：核心价值不足，或硬风险无法接受

不要用模糊总分代替硬门槛。许可证不明、来源无法确认、核心依赖不可得、功能不存在或 README 与代码严重矛盾时，必须显式降级。

### 8. 交付研究结果

读取 [report-format.md](references/report-format.md)。结论先行，随后给出对象说明、内容地图、深度拆解、核验、行动判断和阅读覆盖单。

用链接就近支撑需要当前事实的结论。默认使用用户语言；中文表达清楚直接，避免把大量术语和流水账堆给用户。

## 停止与升级条件

- 页面或来源打不开：尝试官方替代入口、存档、搜索、仓库、文档或图片线索；仍受阻时说明缺口，不伪装成功。
- 需要用户已登录状态：使用用户指定或当前可用浏览器；认证仍阻塞时，明确请用户在该浏览器完成登录。
- 研究范围开始无限扩张：在所有会改变“使用/复刻/二开”判断的关键链路已核验后停止，并列出未追踪的次要链接。
- 用户决定继续试用：提出最小但真实的验证方案，得到许可后再安装、运行或调用付费服务。
- 用户决定正式复刻或二开：把本次证据、可复用点、风险和未决问题交接到产品或开发流程，不在本 Skill 内偷偷扩张范围。
