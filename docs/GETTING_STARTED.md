这份指南只解决一件事：从第一次听说格物，到成功完成第一次调查。

## 你会得到什么

把一个链接、仓库、文章、截图或产品线索交给格物，它会尽量完成四件事：

1. 把影响判断的材料看完整
2. 找到官网、原仓库或一手发布者
3. 区分已经核实的事实、来源自己的说法、合理推断和未验证项
4. 告诉你下一步应该使用、试用、复刻、二开、继续观察，还是停止投入

格物不是网页摘要器。它的目标是帮你形成一份可以采取行动的判断。

## 方式一：在 Codex / ChatGPT Work 中安装插件

这是最省事的安装方式。

### 第一步：添加格物插件市场

打开 **插件 → 添加插件市场**，填写：

| 字段 | 填写内容 |
| --- | --- |
| 来源 | `wuxie888/gewu` |
| Git 引用 | `main` |
| 稀疏路径 | 留空 |

![在 Codex 中添加格物插件市场](../assets/plugin-marketplace-add.png)

点击 **添加市场**。

这个入口是 Codex 的官方能力，但手动添加的 Git 市场属于第三方供应链，并不会自动获得 OpenAI 审核背书。添加前请确认：

- 来源准确为 [`wuxie888/gewu`](https://github.com/wuxie888/gewu)
- 仓库公开可读，作者、提交历史和插件清单与本项目一致
- 当前格物只包含 `skills/`，没有 App、MCP Server、Hook 或要求登录的远程服务

`main` 会持续获得最新修订。如果你更重视可复现性，可以把 Git 引用固定为稳定 tag `v1.1.0` 或完整 commit SHA。

### 第二步：安装格物

在刚刚添加的格物市场中找到 **格物 · Gewu**，点击 **安装**。

如果你更习惯命令行，也可以运行：

```bash
codex plugin marketplace add wuxie888/gewu
codex plugin add gewu@gewu
```

### 第三步：新建一个任务

安装完成后，新建一个 Codex / ChatGPT Work 任务。已经打开的旧任务不会自动重新载入刚安装的插件。

在新任务中显式调用：

- Codex：输入 `$gewu`，或从 Skill 选择器中选择 **格物 · Gewu**
- ChatGPT Work：如果 `@` 菜单中显示 **格物 · Gewu**，从菜单中选择它

发送之前，确认编辑框中已经出现 `$gewu` 或已选中的格物 Skill。仅仅得到一段像调查报告的回答，并不能证明插件已经被加载。

### 已经安装过格物

仓库发布新版本后，不要假设本机插件会立即自动更新。刷新 Git 市场并重新同步已安装插件：

```bash
codex plugin marketplace upgrade gewu
```

刷新后新建任务。`codex plugin marketplace add wuxie888/gewu` 只用于第一次添加市场，不是升级命令。

## 完成第一次调查

复制下面这句话，把最后的链接换成你真正想调查的对象：

```text
$gewu 完整查看这个链接，告诉我它是什么、源头在哪里、哪些说法已经核实，以及值不值得继续研究：
https://example.com
```

第一次建议使用一个公开可访问的产品网站、GitHub 仓库或普通文章。登录、验证码、地区限制和浏览器安全策略可能让第一次体验只能进入降级调查。

## 怎样判断格物已经正常工作

一次正常的格物调查通常会包含：

- **范围**：看了哪些页面、图片、回复、外链、源码或文档
- **对象与来源**：它到底是什么，一手来源在哪里
- **证据分层**：哪些是直接观察，哪些只是来源声称或合理推断
- **拆解**：产品、技术、设计、写作或商业方法
- **结论**：值得使用、试用、复刻、二开、观察，还是停止投入
- **边界**：哪些内容没有看到，为什么没有看到

如果材料打不开，格物应明确写出“降级调查”，而不是假装完成了完整审阅。

## 直接可用的提问

### 看产品网站

```text
$gewu 完整看一下这个产品网站，拆解功能、交互和商业模式，并判断值不值得用。
```

### 看 GitHub 仓库

```text
$gewu 深查这个 GitHub 仓库的源码、许可证、维护状态和真实完成度，判断是否适合二次开发。
```

### 看文章或推文

```text
$gewu 完整看完这篇文章和关键配图、引用、回复与外链，分析其中项目的可行性。
```

### 反查被隐藏的产品

```text
$gewu 文章没有写产品名，请从截图、Logo、界面文字和功能描述中反查原项目，并交叉确认。
```

### 拆写作方法

```text
$gewu 拆解这篇文章的结构、叙事节奏、证据使用和传播方法，给我一套可执行但不照抄原文的写作框架。
```

### 只做快速判断

```text
$gewu 先快速判断这个东西是否值得继续研究，不需要完整深查，但请说明当前证据边界。
```

## 方式二：在其他 Agent 中安装 Skill

格物的可移植核心是整个 [`skills/gewu/`](../skills/gewu/) 目录。

1. 把该目录复制到目标 Agent 的 Skills 或 Instructions 目录
2. 如果平台没有原生 Skill 机制，把 `SKILL.md` 作为系统或开发者指令加载
3. 确保 Agent 可以按相对路径读取 `references/`
4. 使用 `gewu`、`格物` 或平台提供的 Skill 选择器显式调用

不同 Agent 的安装位置和触发语法可能不同，但调查流程和证据标准不绑定于 Codex。

## 遇到问题

先查看 [常见问题与排错](./TROUBLESHOOTING.md)。如果问题仍然存在，请在 [GitHub Issues](https://github.com/wuxie888/gewu/issues) 提交：

- 使用的平台和版本
- 安装方式
- 触发方式
- 实际看到的错误
- 可以公开复现的链接

不要在 Issue 中提交私有链接、账号、Cookie、API Key 或其他敏感信息。
