## 由测试驱动的修订

第一次 GitHub 测试暴露出一个真实权限缺口：旧规则允许在“结论依赖运行”时自行升级到安装和构建。现在规则已改为：

- 默认只读，不克隆、安装、构建或运行第三方代码
- “完整看”“深度分析”“值不值得使用或二开”都不等于授权执行
- 只有用户明确说“测试、构建、运行、跑一下、来试试”等，才允许进入 E3
- 历史运行记录可以作为注明日期的旁证，不能冒充本次验证

第二次对同一仓库盲测后，代理正确停在 E2，说明修订已产生预期行为。

## 已验证的核心行为

- 页面完整性优先于正文提取
- Chrome 可访问时检查图片、视频、回复和关键外链
- 页面受限时保留未完成状态，并给出覆盖数量
- 作者声称、直接观察、交叉验证、推断和未验证项分开表达
- GitHub 调查读取真实文件和维护信号，但不越权执行代码
- 最终结论明确区分直接使用、学习、复刻、二开与停止投入
- 来源追踪是调查的一部分，不会挤占产品、技术、设计、内容和可行性分析

## 仍需长期回归的边界

- 登录态、验证码、地区限制和反自动化页面随站点变化，无法保证每次都能完整渲染
- 无限滚动与动态回复只能报告实际检查数量和停止位置，不能承诺数学意义上的“全部”
- 视频、音频和大量配图需要按决策相关性分层检查；未逐项查看时必须写入覆盖单
- 第三方站点结构变化后，应重新执行对应真实链接测试
